# CLAUDE.md — rules for AI assistants working on LAST SIGNAL

## Non-negotiables
- **Engine: Godot 4.7.2-stable. Language: GDScript only.** Native .tscn / .gd / .tres / project.godot. No Unity, Unreal, Phaser, JS/HTML gameplay, C#, or third-party frameworks. Don't switch engines; if something is hard in Godot, explain and propose a Godot-native solution.
- Use **Godot 4.7 APIs** (e.g. `TileMapLayer`, not the deprecated `TileMap`; `CharacterBody2D.velocity` + `move_and_slide()`; typed GDScript). Check the official docs for anything uncertain.
- Renderer: **Compatibility** (required for web export).
- Zero-cost: no paid assets/APIs/services/backends without the owner's explicit approval. No unnecessary plugins.
- Original content only. Every external asset must be verified for commercial use **before** use and recorded in `ASSET_LICENSES.md`.

## Workflow
1. Inspect before modifying. Never overwrite blindly. Never delete important files without approval.
2. Git commit before substantial changes.
3. Small increments: build → validate → fix → expand.
4. Validation after every change:
   - `godot --headless --path . --import` (no errors)
   - parse check of all scripts, load every scene
   - `godot --headless --path . --script res://tests/run_tests.gd` (all pass)
5. Statuses: NOT STARTED / IN PROGRESS / IMPLEMENTED / TESTED / VERIFIED / BLOCKED. Never call something VERIFIED until the owner has play-tested it. Never call placeholder art "final".
6. End each phase with a report: implemented features, modified files, tests + results, problems, manual test steps for the owner, next phase.
7. Keep README, CHANGELOG, GDD, QA_CHECKLIST, ASSET_LICENSES current.
8. Label every test result `[LINUX-AUTO]`, `[WIN-AUTO]`, `[WIN-PLAY]`, `[WEB-EXPORT]` or `[VISUAL]`. Linux results (headless or software-GL renders) are never presented as proof of Windows, browser or visual correctness.
9. Git: the owner runs commits on Windows. Never run `git reset`, `git clean`, `git checkout -- <file>`, force-push, or delete or overwrite existing files without explicit owner approval. Don't request broad delete permissions just for Git.
10. Don't start a new phase until the owner explicitly approves it.
11. Every validation run includes the playthrough bot (whole game to the ending, 5 seeds) and the memory soak test (Phase 11). A level or quest change that breaks the bot is a bug, not a test to loosen.

## Code style
- `snake_case` files/functions/variables, `PascalCase` classes/nodes, `UPPER_CASE` constants.
- Static typing everywhere (`var speed: float = 80.0`, `func f(x: int) -> void`).
- Scripts under ~300 lines; split into components if bigger.
- Gameplay numbers live in `data/*.tres` resources, not hard-coded.
- Signals for "something happened"; direct calls for "do this". Global events go through `EventBus`.
- No per-frame group lookups or raycasts in hot paths; use the AI think tick.
- Interior darkness = local Subtract `PointLight2D` per DarkZone (never a whole-scene `CanvasModulate` for interiors). Roofs/outer walls are excluded via light cull masks.
- Player damage must never depend on player state (except DEAD). No invincibility frames.
- Quest-critical items come only from `guaranteed_items` in designated containers, never from random tables.
- Helper or test scripts that use autoloads (`AudioManager`, …) must run as a **scene**, not via `--script` (autoloads aren't loaded in `--script` mode).
- Never give corpses or decals a negative `z_index` (they disappear under the TileMapLayers).
- The navigation server syncs in the background (~10–15 physics frames after a region appears). Tests must wait for a non-empty path, not a fixed frame count; gameplay code must fall back to straight movement.
- Don't change difficulty values without measured scenario data **and** the owner's play-test.
- Scenes are generated by Claude's builder script until the owner starts editing them in the Godot editor. Before regenerating any `.tscn`, check (checksums) that the owner hasn't edited it. If they have, edit the scene in place instead.
- Containers: never reuse a `container_id`; the designated quest ids are listed in tests/test_world.gd.
- Night siege (Slice 1): all cycle/horde/Heat/barricade numbers live in `data/siege/siege_data.tres`. Measure changes with `tests/scenarios/siege_scenarios.tscn` and get the owner's play-test before calling them final. Never restock quest containers. Zombies may path through windows (navigation layer 2); everything else uses layer 1.

## Owner context
Solo beginner developer (Windows, Ryzen 5 5600H, 8 GB RAM). Explain important decisions briefly and plainly. When the owner must do something in the editor, say exactly what to click and what result to expect.
- Run state that must survive respawns (and later saves) lives in the `GameState` autoload: rolled container contents, item piles / death backpacks, stats. Never store it only in scene nodes.
- Container searching is a timer on the Player (`start_search` / `cancel_search`), deliberately **not** a Player state, so the verified state machine stays unchanged.
- Tests that touch loot or backpacks call `GameState.new_game(seed)` first (GameState persists between tests).
- UI text uses the project theme's pixel font: only font sizes 10 (1:1) and 20/30 (2×/3×) look crisp. Build panels with `UiKit` (scripts/ui/ui_kit.gd); don't hard-code other font sizes.
- Gameplay timers must pause with the game: `get_tree().create_timer(t, false)`. Menus that must work while paused use `PROCESS_MODE_ALWAYS`.
- The start scene is `scenes/ui/main_menu.tscn`; tests and tools instantiate `scenes/main/game.tscn` directly.
- Cosmetic randomness (sounds, particles, visual variation) must use a local `RandomNumberGenerator`, never `randf()/randi()`, so gameplay randomness stays reproducible.
- Art/sound are generated by `tools/asset_generators/*.py`; change the generator and re-run it rather than editing the PNG/WAV by hand. Character sheet layouts must match `PLAYER_ANIMS` / `WALKER_ANIMS`.
- Saving: `SaveSystem` autoload. Anything new that must survive quitting goes into `GameState.to_dict()/from_dict()` (world) or `Player.to_save_dict()` (player); bump `SaveSystem.VERSION` and add a step to `migrate()` when the format changes. Tests and tools must set `SaveSystem.path` to their own file (the test runner does).
